## 1. 测试策略

### 1.1 测试金字塔

```
           /──────────────\
          /   E2E测试 (10%)  \   端到端，模拟真实用户操作
         /  核心用户流程全覆盖   \
        /──────────────────────────\
       /    集成测试 (20%)           \  模块间协作、数据层集成
      /     Repository、Service、Store  \
     /────────────────────────────────────\
    /        单元测试 (70%)                 \  函数、组件、工具函数
   /     核心逻辑覆盖率≥80%，整体≥60%       \
  /────────────────────────────────────────────\
```

### 1.2 覆盖率目标

| 层级 | 整体目标 | 核心模块目标 | 说明 |
|------|----------|-------------|------|
| 语句覆盖率 | ≥60% | ≥80% | 可执行语句被测试覆盖 |
| 分支覆盖率 | ≥50% | ≥70% | if/else/switch分支被覆盖 |
| 函数覆盖率 | ≥60% | ≥80% | 函数被调用 |
| 行覆盖率 | ≥60% | ≥80% | 代码行被执行 |

**核心模块**：stores/、domain/、utils/、editor/markdown-parser、graph/force-layout、search/search-service

### 1.3 测试类型

| 类型 | 框架 | 运行时机 | 目标 |
|------|------|----------|------|
| 单元测试 | Vitest | 每次提交、CI | 函数、组件、工具函数正确性 |
| 组件测试 | Vitest + Testing Library | 每次提交、CI | React组件渲染、交互 |
| 集成测试 | Vitest | 每日构建、CI | 模块间协作、数据层 |
| E2E测试 | Cypress | 每日构建、发布前 | 核心用户流程端到端 |
| 性能测试 | k6 + Lighthouse | 每周、发布前 | 性能基准、性能退化检测 |
| 视觉回归 | Chromatic（可选） | 每周 | UI视觉一致性 |
| 可访问性 | axe-core | 每周 | WCAG可访问性合规 |
| 安全测试 | npm audit + njsscan | 每周、发布前 | 依赖漏洞、代码安全 |

## 2. 单元测试方案

### 2.1 框架选型：Vitest

| 特性 | Vitest | Jest | 结论 |
|------|--------|------|------|
| 与Vite集成 | 原生 | 需要额外配置 | ✅ Vitest |
| 启动速度 | 极快（ESM原生） | 较慢（需要transform） | ✅ Vitest |
| HMR | 支持 | 不支持 | ✅ Vitest |
| API兼容 | Jest兼容 | 标准 | ✅ 两者均可 |
| 类型推断 | TS原生 | 需要额外配置 | ✅ Vitest |
| 生态成熟度 | 快速增长 | 非常成熟 | ⚠️ Jest略优 |

**选择Vitest**：与OneOS的Vite构建工具原生集成，启动快，HMR支持，API与Jest兼容，迁移成本低。

// tests/integration/note-workflow.test.ts
describe('笔记完整工作流集成测试', () => {
  it('新建笔记→搜索可搜到→图谱显示节点→删除笔记→搜索和图谱同步删除', async () => {
    // 1. 新建笔记
    const note = await noteStore.createNote({ title: '集成测试笔记', content: '测试内容' });
    
    // 2. 验证笔记存储
    expect(await noteRepository.findById(note.id)).not.toBeNull();
    
    // 3. 验证搜索可搜到
    const results = await searchService.search('集成测试');
    expect(results.some(r => r.id === note.id)).toBe(true);
    
    // 4. 验证图谱显示节点
    const graphData = await graphDataService.buildGraph();
    expect(graphData.nodes.some(n => n.id === note.id)).toBe(true);
    
    // 5. 删除笔记
    await noteStore.deleteNote(note.id);
    
    // 6. 验证搜索同步删除
    const resultsAfter = await searchService.search('集成测试');
    expect(resultsAfter.some(r => r.id === note.id)).toBe(false);
    
    // 7. 验证图谱同步删除
    const graphDataAfter = await graphDataService.buildGraph();
    expect(graphDataAfter.nodes.some(n => n.id === note.id)).toBe(false);
  });

## 4. E2E测试方案

### 4.1 框架选型：Cypress

| 特性 | Cypress | Playwright | 结论 |
|------|---------|------------|------|
| 调试体验 | 极佳（时间旅行、截图、录屏） | 优秀 | ✅ Cypress略优 |
| 学习曲线 | 平缓 | 中等 | ✅ Cypress |
| 浏览器支持 | Chrome/Firefox/Edge | 所有（含Safari） | ⚠️ Playwright |
| 社区生态 | 非常成熟 | 快速增长 | ✅ Cypress |
| 移动端支持 | 有限 | 较好 | ⚠️ Playwright |

**选择Cypress**：调试体验极佳，社区生态成熟，学习曲线平缓，适合OneOS当前阶段。

### 4.2 核心用户流程（E2E覆盖）

| 流程ID | 流程名称 | 优先级 | 包含步骤 |
|--------|----------|--------|----------|
| E2E-001 | 应用启动 | P0 | 打开应用→仪表盘加载→无报错 |
| E2E-002 | 笔记CRUD | P0 | 新建笔记→编辑内容→保存→搜索→删除 |

## 9. 附录

### 9.1 测试数据规范

- **测试数据隔离**：每个测试用例独立，不依赖其他用例的数据
- **测试数据生成**：使用fixtures + mock-data生成器，不硬编码
- **测试数据清理**：afterEach清理，避免数据污染
- **真实数据模拟**：使用接近真实的数据量（如1000条笔记）测试性能

### 9.2 测试命名规范

```
测试文件：<被测模块>.test.ts / <被测模块>.spec.ts
测试套件：describe('<模块名>', () => { ... })
测试用例：it('应该<预期行为>', () => { ... })
```

**示例**：
```typescript
describe('MarkdownParser', () => {
  describe('标题解析', () => {
    it('应该正确解析一级标题', () => { ... });
    it('应该正确解析六级标题', () => { ... });
  });
});
```

### 9.3 测试最佳实践

1. **AAA模式**：Arrange（准备）→ Act（执行）→ Assert（断言）
2. **一个测试一个断言主题**：每个测试只验证一个行为
3. **测试描述清晰**：从描述就能知道测试什么、预期什么
4. **避免测试间依赖**：测试顺序不影响结果
5. **Mock外部依赖**：只测试当前单元，不依赖外部
6. **测试也要维护**：代码重构时同步更新测试
7. **优先测试边界**：边界条件比正常情况更容易出bug
8. **测试失败信息清晰**：失败时能快速定位问题
